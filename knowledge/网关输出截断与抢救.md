# 网关输出截断与抢救

判读走 SMS 纯文本网关，模型输出是 JSON 文本；`max_tokens` 不够时回复被截断
（`finish_reason=length`），旧版解析失败后把字段填空，冒充"正常结果"。

## 症状与根因

- 现象：`type/feeling/object/emotion/requirement/evidence` 全是默认空值，
  而 `raw` 里的判读其实完整正确。
- 根因：JSON 超出输出预算被截断，大括号不平衡，`json.loads` 失败。
- 实测：alarm 的一次完整判读约需 2400 completion tokens，默认 1024 必截。

## 三道防线（scripts/perceive.py）

1. **预算前置**：SYSTEM 写明输出预算——feeling ≤6 词；object.top3 恰 3 项且
   name ≤12 字；reasoning ≤120 字；evidence ≤6 条且 implies ≤40 字；
   uncertainty ≤3 条；`usage` 与 `audio_encoding_digest` 不回显（本地自填）；
   并硬要求 feeling/uncertainty 用 JSON 数组、evidence 用对象数组。
2. **默认 2048**：`perceive()` 与 CLI `--max-tokens` 默认提到 2048，可显式覆盖。
3. **截断抢救**：`_salvage_json()` 先剥代码围栏，再从首个 `{` 做括号平衡扫描
   （忽略字符串内的括号与转义）；未闭合则回退到最后一个「值已完整」边界，
   按未闭合栈补齐 `]`/`}` 后 `json.loads`；成功件附 `"truncated": true`。

## feeling 的归属与 normalize 边界（现状）

`feeling` 属**模型产出**：`normalize()` 只对它做类型归一与截断——
`_as_list(out["feeling"], r"[、，,;；\s]+")[:6]`，即模型写成一句话时按顿号/逗号/分号/空白拆分，
最多保留 6 项；模型已给的听感词**不会被默认值覆盖**，也不从声学编码回填
（与 `audio_encoding_digest` 缺省回填 `enc["tokens"]`、`usage` 本地自填不同）。
1.0.0 曾以「非 list 即置默认」处理，字符串型 feeling 被整条丢弃为 `[]`（吞字段），现已修。
失效条件：模型未给＝空数组（不得臆造）；`truncated`/`parse_failed` 件里 feeling 可能缺失或仅部分抢救，
交付须随件标注，不得当作「模型判定无听感」。

## 失败与唯一重试

- 彻底救不回：写 `"parse_failed": true` 并保留 `raw` 全文（截 4000 字），
  不得用空字段冒充正常结果。
- 唯一重试例外：`finish_reason=="length"` 且抢救失败时，追加
  「只输出压缩 JSON，evidence≤3 条」再调一次网关；其余失败一律即停，
  见 [失败即停不重试](../resistance/失败即停不重试/失败即停不重试.md)。

## 实测（tmp/samples，模型 SCNet-Max）

- alarm `--max-tokens 2048`：finish=stop，type=警报 0.86，evidence 6 条，无 truncated。
- alarm `--max-tokens 120`：被截断，抢救回 `type`（警报 0.91）并标 `truncated=true`。
- gunshot / chord / speech_like：2048 下均无截断、无 parse_failed。
